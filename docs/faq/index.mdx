## 我没有项目，应该从哪里开始？

先看[准备账号、项目和权限](../getting-started/prepare.mdx)。公司已有项目时向管理员申请测试/开发项目的使用权限；尚未开通时按官方开通和项目创建指南操作。不要猜测项目名或复制其他地域的 Endpoint。

## 第一次查询需要已有业务表吗？

不需要。[第一条查询](../getting-started/first-query.mdx)使用常量 SELECT，内联样例也不依赖已存在的表。它们仍需可执行 SQL 的项目与身份，不代表免费或免授权。

## 我该安装哪个工具？

[按任务选择工具](../getting-started/client-selection.mdx)，先选一个。图形界面、终端、Java 程序和已有 Spark/Flink 工程分别有不同入口。

## 能登录，为什么仍提示权限不足？

身份认证和项目、表权限是不同的检查。确认实际身份已加入目标项目；业务表查询还需目标对象的读权限。请项目管理员按[官方授权指南](https://help.aliyun.com/zh/maxcompute/user-guide/user-planning-and-management)核对，不默认申请管理员权限。

## Endpoint 该填哪个？

使用[官方连接地址列表](https://help.aliyun.com/zh/maxcompute/endpoints)，同时匹配项目地域和当前网络。连接超时先检查地址与网络；认证失败再核对身份和凭据有效期，不通过关闭 TLS 校验解决问题。

## 安装、查询或结果读取失败，如何定位？

| 失败阶段                 | 先检查                              | 下一步                                                                                                                                             |
| ------------------------ | ----------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------- |
| 找不到命令或驱动         | 当前环境、版本、架构与安装目录      | [CLI 安装](../products/cli/installation.mdx)、[JDBC 排障](../products/jdbc/troubleshooting.mdx)、[ODBC 排障](../products/odbc/troubleshooting.mdx) |
| 认证或连接失败           | 项目、地域、Endpoint、身份与授权    | [准备清单](../getting-started/prepare.mdx)                                                                                                         |
| SQL 执行失败             | 服务端作业错误、对象权限和 SQL 类型 | 所选产品的故障排查与官方 SQL 文档                                                                                                                  |
| 等待超时                 | 已返回的作业标识与服务端状态        | [CLI 作业超时](../products/cli/troubleshooting.mdx#作业超时)，先查询原作业，不盲目重提                                                             |
| 作业成功但下载失败       | 结果通道、网络和下载权限            | [JDBC 分层排障](../products/jdbc/troubleshooting.mdx)                                                                                              |
| dbt 解析、构建或测试失败 | 失败节点、版本、Profile 与编译 SQL  | [dbt 排障](../products/dbt/troubleshooting.mdx)                                                                                                    |

## 搜不到页面怎么办？

尝试 `JDBC 连接`、`dbt 升级` 等产品加任务的关键词，或粘贴不含敏感信息的错误类型。先切换到“全部文档”，减少无关词；仍无结果时按任务目录和故障阶段查找。

## 文档草稿是否意味着产品未 GA？

不是。草稿是页面的内容状态，产品成熟度与已发布能力见[各产品版本说明](../updates/index.mdx)。升级时同时核对安装包、运行时与使用限制。

## 入门完成后如何清理？

常量查询与内联数据分析不创建表，无需删除项目。dbt 等写表教程须单独核对测试对象并按教程清理；`dbt clean` 不删除云端表。不要把清理测试数据扩大成删除已有业务对象。

## 提交问题时需要哪些信息？

提供工具版本、操作系统、失败阶段、完整错误类型、脱敏 SQL 与作业 ID。不要提交凭据、Profile 原文、客户数据或带签名的链接。可从[产品目录](../products/index.mdx)进入对应排障页查反馈入口。
