## Profile

| 字段                                  | 含义                | 入门值 / 约束                                   |
| ------------------------------------- | ------------------- | ----------------------------------------------- |
| `type`                                | Adapter 类型        | `maxcompute`                                    |
| `project`                             | 项目                | 必填                                            |
| `schema`                              | 模型 schema         | 填已存在且获准使用的命名空间                    |
| `endpoint`                            | MaxCompute Endpoint | 必填，与项目地域和网络匹配                      |
| `auth_type`                           | 认证方式            | 入门使用 `access_key`                           |
| `access_key_id` / `access_key_secret` | 身份凭据            | 通过 `env_var` 引用                             |
| `security_token`                      | STS Token           | STS 认证须核对上游对应 auth_type 与整组临时凭据 |
| `threads`                             | dbt 并发            | 入门为 1，不是 Spark 并行度                     |

`dbt_project.yml` 的 `profile` 必须与 `profiles.yml` 顶层名称相同。schema 命名和自定义 schema 宏应以项目实际策略为准；不要假定 dbt 自动把数据隔离进某个个人 schema。

完整认证配置见[上游认证文档](https://github.com/aliyun/dbt-maxcompute/blob/master/docs/authentication.md)。

## 模型配置

| 配置            | 用途           | 注意                                            |
| --------------- | -------------- | ----------------------------------------------- |
| `materialized`  | 物化方式       | `table` 会重建目标                              |
| `tblproperties` | 表属性字典     | 例如 `table.format.version: '2'`                |
| `transactional` | 事务表属性     | 表属性不意味着 dbt 支持 BEGIN/ROLLBACK          |
| `primary_keys`  | 物理主键列     | SQL table 的 PK Delta 建表配置                  |
| `unique_key`    | 增量数据匹配键 | 不创建物理主键                                  |
| `partition_by`  | 分区字段与类型 | 例如 `{'fields': 'ds', 'data_types': 'string'}` |
| `lifecycle`     | 表保留天数     | 谨慎配置                                        |
| `sql_hints`     | SQL 设置       | 修改前核对服务端语义与版本                      |

模型配置基于[官方 Adapter README](https://github.com/aliyun/dbt-maxcompute#configure-your-dbt-models)，新建表属性与已有表迁移分别处理。

## Python 运行时兼容

1.11.3 延续 beta 的全局 SQL 默认值 `odps.sql.python.version=cp311`，对 dbt `function()` 引用和直接写函数名的 SQL 调用均生效。1.11.2 未全局设置此 hint，因此从 1.11.2 升级时，调用已有 Python 2.7 / 3.7 UDF 的模型必须显式使用匹配的 `cp27` / `cp37`：

```sql
{{ config(sql_hints={'odps.sql.python.version': 'cp27'}) }}
```

Python 3.7 函数改用 `cp37`。调用旧函数的 hook 需在自己的 SQL 中加入对应的 `SET odps.sql.python.version=cp27;` 或 `cp37`。同一 SQL 语句不能混用不兼容的 Python 运行时。

`dbt show --select` 的 Core 预览路径不应用模型 `sql_hints`，预览旧版函数时还需配置对应的 `sql_header`，例如 Python 3.7：

```sql
{{ config(
    sql_hints={'odps.sql.python.version': 'cp37'},
    sql_header='SET odps.sql.python.version=cp37;'
) }}
```

新建 dbt Python 函数须有有效的 `runtime_version`，可在 `dbt_project.yml` 设置项目默认值：

```yaml
functions:
  +runtime_version: '3.11'
```

`runtime_version` 用于源代码校验和兼容性报告，不替代调用端的 SQL 运行时 hint；CP27 提醒针对已有旧函数调用，不表示可用此适配器新建 CP27 函数。CP37 函数可显式声明兼容运行时，依赖资源也必须匹配 CP37，不能复用为 CP311。详见 [1.11.3 UDF 运行时说明](https://github.com/aliyun/dbt-maxcompute/blob/v1.11.3/docs/python-udfs.md)。

## 可选配置

- `incremental_strategy='truncate_insert'`：非分区整表替换，需同时设置 `full_refresh=false`，返回完整数据并核对限制；见[模型指南](./guides.mdx#可选整表替换truncate_insert)。
- `catalog_strict_metadata`：严格元数据检查仍为可选项，默认 `false`；元数据不完整会产生警告。不要把 catalog 生成成功等同于元数据完整。

## 命令与产物的含义

| 命令 / 产物               | 能证明什么                                           |
| ------------------------- | ---------------------------------------------------- |
| `dbt parse`               | 项目可解析，生成 manifest；不验证模型 SQL 的云端执行 |
| `dbt compile`             | 模板编译；宏可调用数据库，不应视为完全离线           |
| `dbt debug`               | Profile 与连接检查                                   |
| `dbt build`               | 所选模型及相关测试的运行结果                         |
| `target/manifest.json`    | 模型、依赖、配置与编译信息                           |
| `target/run_results.json` | 各节点运行状态、耗时与 Adapter 响应                  |
| `dbt docs generate`       | 文档和元数据 catalog 生成                            |

这些产物可能含 SQL、对象名和元数据，应在分享前脱敏。MaxCompute 不返回可靠 DML 影响行数，`rows_affected` 不用作写入完整性依据。Adapter 的 `BEGIN`、`COMMIT`、`ROLLBACK` 不提供传统多语句事务；失败后需逐对象核对。

命令定义参见 [dbt 官方命令文档](https://docs.getdbt.com/reference/dbt-commands)。
